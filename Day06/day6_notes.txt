## Linux Networking Fundamentals

   1. An IP address is a unique numerical label assigned to every device connected to a computer network that uses the Internet Protocol for communication. It serves as the device's network identifier and location address. [1, 2, 3, 4] 
   2. A private IP is used within a local network (like your home or office Wi-Fi) and cannot be routed over the public internet. A public IP is unique across the entire world and allows devices on the global internet to find and talk to your network. [5, 6, 7, 8, 9] 
   3. DNS (Domain Name System) is the phonebook of the internet. It translates human-readable domain names (like google.com) into computer-readable IP addresses (like 142.250.190.46). [10, 11, 12, 13, 14] 
   4. ping sends small test data packets (ICMP Echo Requests) to a network destination and measures how long it takes to get a response. It checks if a remote device is online and evaluates network latency. [15, 16, 17, 18, 19] 
   5. ping 8.8.8.8 tests direct connectivity to a specific numerical IP address, bypassing DNS completely. ping google.com forces your machine to first talk to a DNS server to resolve the name to an IP address before it can send the test packets. [20, 21, 22] 
   6. nslookup is a command-line tool used to query DNS servers directly. It helps find the IP address associated with a domain name or find the domain name associated with an IP address. [23, 24, 25, 26, 27] 
   7. An A record maps a domain name to a 32-bit IPv4 address (e.g., 192.168.1.1). An AAAA record maps a domain name to a 128-bit IPv6 address (e.g., 2001:db8::1). [28, 29, 30, 31, 32] 
   8. curl is a command-line tool used to transfer data to or from a network server using various protocols (like HTTP, HTTPS, or FTP). DevOps engineers use it to interact with APIs, download files, and inspect response headers. [33, 34, 35, 36] 
   9. curl outputs data directly to your terminal screen by default and is optimized for interacting with APIs and complex scripts. wget saves downloaded content straight to a file by default, supports recursive downloading (saving whole websites), and automatically resumes broken downloads.
   10. ss -tuln displays all active network sockets. It specifically filters for TCP, UDP, Listening sockets, and shows numerical addresses and port numbers (N) instead of resolving them to service names. [37, 38] 
   11. LISTEN indicates that a background application or service is active and waiting for clients to connect to its assigned port number.
   12. 0.0.0.0:8080 means that a network application running on port 8080 is accepting traffic from every network interface configuration on that machine, including localhost, local Wi-Fi, and public internet IPs.
   13. SSH (Secure Shell) is a secure, encrypted network protocol used to safely access, control, and run commands on a remote Linux server over an unsecure network. [39, 40] 
   14. Port 22 is the default network port used for SSH connections. [41] 
   15. SCP (Secure Copy Protocol) is a command-line tool used to securely copy files and directories between local and remote Linux hosts. It encrypts the data transfer by running directly on top of the SSH protocol.
   16. traceroute tracks and displays the exact path (the specific routers and hops) a data packet takes to reach its destination, helping you pinpoint exactly where a network connection is failing or slowing down. [42, 43, 44] 
   17. Your DNS configuration is broken. The successful ping to 8.8.8.8 proves your internet connection is active, but the failure to ping google.com shows your system cannot translate domain names into IP addresses. [45, 46] 
   18. No application or service is listening on port 8080. The application is either completely turned off, failed to start, or crashed. [47] 
   19. The application on port 8080 is running perfectly. An HTTP 200 status code indicates that the web server successfully received, processed, and responded to your network request.
   20. To troubleshoot an unreachable website, follow these systematic steps:
   * Run ping on the target IP to check basic network connectivity.
      * Run nslookup on the domain name to ensure DNS resolution works.
      * Run traceroute to see if the network path breaks down at a specific external router.
      * Run ss -tuln | grep <port> on the destination server to verify the web service is actively listening.
      * Check local firewall rules (like ufw status or iptables) and Cloud Security Groups to make sure incoming traffic on the port is not blocked. [48, 49, 50]
